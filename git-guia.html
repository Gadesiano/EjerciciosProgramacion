⚙️ Configuración inicial

git config --global user.name
git config --global user.email
git config --global user.name "Nombre"
git config --global user.email "email"

El flag --global aplica la configuración a todos los repositorios de la máquina. Sin él, la configuración sería solo para el repositorio actual.

📋 Comandos utilizados

Comando Descripción
git init
Inicializa un repositorio Git vacío en la carpeta actual.
Crea la carpeta oculta .git/ donde Git guarda todo el historial. No tocar manualmente.
git status
Muestra el estado actual del repositorio: ficheros sin trackear, en staging o modificados.
El comando más usado en el día a día. Ejecutar constantemente para saber en qué punto estás.
git add .
Añade todos los ficheros no ignorados al área de staging (los prepara para el commit).
El punto significa "todo". También se puede añadir un fichero concreto: git add archivo.cs
git commit -m "mensaje"
Crea un commit con los ficheros en staging y el mensaje indicado.
El mensaje debe seguir la convención de commits del proyecto (ver sección siguiente).
git branch -m <antiguo> <nuevo>
Renombra una rama local.
Usado para renombrar master a main, el nombre estándar actual en GitHub.
git remote add origin <url>
Enlaza el repositorio local con un repositorio remoto en GitHub.
origin es el alias estándar para el remoto principal. Solo se ejecuta una vez por repositorio.
git remote -v
Muestra los remotos configurados y sus URLs.
Aparecen dos líneas por remoto: una para fetch (descargar) y otra para push (subir). Normalmente son la misma URL.
git push -u origin main
Sube los commits locales a GitHub por primera vez y establece el upstream por defecto.
El flag -u solo se usa la primera vez. A partir de ahí basta con git push.
git push
Sube los commits locales al remoto configurado por defecto.
Funciona tras haber ejecutado git push -u origin main al menos una vez.

🔄 Flujo de trabajo básico

Modificar ficherosWorking directory
→
git addStaging area
→
git commitRepositorio local
→
git pushGitHub (remoto)

Git tiene tres zonas locales: el working directory (tus ficheros), el staging area (lo que has marcado para commitear) y el repositorio local (el historial de commits). GitHub es el repositorio remoto.

✍️ Convención de commits

Se usa el estándar Conventional Commits. Hace el historial legible, profesional y filtrable.

feat
Nueva funcionalidad

Añadir un ejercicio nuevo, una feature o una capacidad al proyecto.

fix
Corrección de bug

Solucionar un error en un ejercicio o en la lógica del proyecto.

chore
Mantenimiento / configuración

Tareas que no afectan al código funcional: setup, .gitignore, configuración de proyecto.

docs
Documentación

Cambios en README, comentarios, guías o cualquier fichero de documentación.

test
Tests

Añadir o modificar pruebas unitarias o de integración.

refactor
Refactorización

Cambios en el código que no añaden funcionalidad ni corrigen errores: mejorar legibilidad, renombrar, reorganizar.

style
Estilo / formato

Cambios de formato, espaciado, indentación. Sin impacto en la lógica.

git commit -m "feat: add fibonacci iterative exercise"
git commit -m "chore: initial project setup"
git commit -m "fix: correct off-by-one error in binary search"
git commit -m "docs: update git reference guide"
